Technical Architecture & Methodology

This web application implements a state-of-the-art deep learning pipeline for human face recognition and classification. Unlike naive pixel comparison or whole-image scaling algorithms, this system extracts invariant facial feature embeddings through a multi-stage geometric and neural processing flow.

1. Aspect Ratio & Resolution Handling

A critical requirement of robust face recognition is aspect-ratio independence. When an input image is uploaded (e.g. 1920×1080 16:9, 500×800 5:8 portrait, or 1000×1000 1:1 square), the system does NOT stretch or warp the whole image to a fixed resolution. Doing so would distort facial proportions (eye distance, nose ratio) and ruin feature matching.

How Aspect-Ratio Invariance is Achieved:

  1. The full-resolution original image is passed into the RetinaFace detector.
  2. RetinaFace computes spatial bounding box coordinates [x1, y1, x2, y2] and 5 key facial landmarks in the original coordinate space.
  3. An Affine Similarity Transformation maps the 5 detected landmarks (left eye, right eye, nose tip, left mouth, right mouth) onto a standardized 112×112 reference face target template.
  4. Only the aligned 112×112 face chip is cropped, intensity-normalized, and passed to the deep neural network.

Because the face chip is normalized independently of the outer frame dimensions, a face registered from a 4K landscape photo is recognized identically in a low-res mobile portrait screenshot!

2. ArcFace Feature Extractor

ArcFace (Additive Angular Margin Loss) is a deep convolutional neural network trained to maximize inter-class face variance and minimize intra-class distance on a hypersphere.

The model maps any 112×112 normalized facial image chip into a high-dimensional feature embedding vector:

Embedding Vector: v = [f_1, f_2, f_3, ..., f_512] where ||v||_2 = 1.0

The resulting 512-dimensional vector encapsulates unique structural characteristics of the individual's face (eye spacing, jawline shape, cheekbone geometry) while remaining invariant to illumination changes, slight expression variations, and background context.

3. Cosine Similarity & Multi-Sample Aggregation

To classify a query face against stored database records, the system computes the Cosine Similarity between the query vector q and every stored vector d:

Cosine Similarity = (q . d) / (||q||_2 * ||d||_2) = q . d (since ||q||_2 = ||d||_2 = 1.0)

Multi-Sample Aggregation Strategy (Maximum Similarity):
If Person A has registered 4 facial sample images in SQLite, the query vector is compared against all 4 embeddings for Person A. The maximum similarity score max(sim_1, sim_2, sim_3, sim_4) is selected as Person A's confidence score.

Decision Rule:
If top maximum similarity S_max ≥ {{ threshold }}, identity is matched as Person Name.
If top maximum similarity S_max < {{ threshold }}, identity is classified as Unknown.

4. Security & Biometric Privacy

  • Biometric embeddings are stored as mathematical binary arrays inside a local SQLite database file.
  • Raw embedding vectors are never exposed or rendered in frontend responses.
  • Uploaded files are sanitized using secure_filename and stored locally with strict file extension validation.
  • This system is designed exclusively for authorized registration and identification experiments with user consent.
